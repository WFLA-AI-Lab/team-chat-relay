# 把 Agent 串成工作流

会创建 Agent 之后，下一步就是让多个 Agent 一起干活——按顺序把几个 Agent 串成一条「工作流」，你的输入流经每个 Agent，被一步步加工成最终结果。

## 一、工作流和流水线是一回事

在擂台里，「工作流」和「流水线」说的是同一件事：按顺序串起来的步骤集合。新建、编辑都在擂台的「流水线」页面（聊天站网址后加 `/arena` 进入）。

## 二、每一步引用一个 Agent

工作流的每一步都可以「引用」一个你已经创建的 Agent（也可以选「自定义步骤」，自己写指令）。引用的意思是：运行时直接使用这个 Agent **当前**的人设和模型——你之后改进了它，工作流自动跟上；万一它被删了，工作流就用创建时存的快照兜底，不会坏。

## 三、一个社团场景

「学习出题助手」工作流，3 步：

1. **出题 Agent**：按主题出一套选择题；
2. **批改 Agent**：按标准答案给作答打分、指出错因；
3. **讲评 Agent**：把错因写成一段易懂的讲解。

运行时，你的输入（主题或作答）依次经过这三步，每步的输出自动成为下一步的输入。

## 四、设计三原则

- **单一职责**：每步只干一件事，结果才稳定；
- **指令具体**：写清楚「输入是什么、要产出什么、注意什么」；
- **角色互补**：生成用 V3（快），评审/推理用 R1（慢但严谨，记得把「最大 token」调大）。

## 五、数据全程可见

每次运行的每一步，实际收到的输入和产出的输出都记录在案，点开就能看。出了问题，一眼就能定位是哪一步。

## 记住一句话

把多个 Agent 串成工作流，就是把「一个人的思考过程」变成「一组 Agent 的分工协作」——每步引用一个 Agent，数据流全程可见，改 Agent 自动生效。
