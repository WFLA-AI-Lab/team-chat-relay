> 探测时间 2026-09-10，全部是**只读**探测（GET 响应头 / 公开页面 / 用不存在的账号试一次登录），
> 没有做任何绕过认证、扫描或爆破的动作。原始记录见 `school-endpoint-probe.txt`。

## 一、这套系统是什么架构（有证据的结论）

| 层面 | 结论 | 证据 |
|---|---|---|
| 应用框架 | **ASP.NET Core MVC**（Razor 视图 + Areas） | `site.css` 里带默认模板注释 `docs.microsoft.com/aspnet/core/client-side/bundling-and-minification`；静态资源是 `wwwroot/lib/...` 结构；`/Home/Error` 返回 500（标准模板的 Error 动作） |
| Web 服务器 | **IIS 10.0**（Windows Server 2016/2019+） | 响应头 `Server: Microsoft-IIS/10.0`；`/web.config` 被请求过滤挡下，返回 gb2312 的 IIS 404 页（"404 - 找不到文件或目录"） |
| 托管方式 | IIS + ASP.NET Core Module（Kestrel 在 IIS 后面） | `X-Powered-By: ASP.NET`；响应里看不到 Kestrel 的 `Server` 头（被 IIS 剥离） |
| 前端 | 服务端渲染 + AJAX；**layui 2.9.18** + Bootstrap + jQuery | 页面引用 `/lib/layui-v2.9.18/layui/layui.css`、`/lib/bootstrap/dist/css/bootstrap.css`、`/lib/jquery/dist/jquery.js` |
| 接口风格 | 统一 JSON 信封 | `{ResultType, Message, Data}`，`ResultType=0` 表示成功（`site.js` 的 `request()` 里判断） |
| 模块/路由 | MVC 经典 `/控制器/动作/参数`，含学生区与社团模块 | `/Home/Login`、`/Home/Error`、`/Stu`（学生区）、`/Stu/Cas/GroupDetail/{id}`（社团模块，你们社团介绍里那个链接就是它） |
| 认证方式 | **经典服务端表单认证 / Session Cookie** | 未登录访问 `/Stu/...` 一律 `302 → /Home/Login?ReturnUrl=...`；**没有任何 OAuth/OIDC/CAS/SAML 痕迹**（没有 `/.well-known`、没有授权端点、没有 JWT） |
| 登录接口 | `POST /Home/Login`，字段 `code` / `password` / `remember` | 实测：无验证码、无 `__RequestVerificationToken`（无防伪令牌）、失败响应带明确文案 |
| 数据层 | **未知**（推测大概率 SQL Server，但无证据，不要拿这句去问） | 栈组合像 SQL Server，但公网侧无法验证 |
| 部署暴露面 | 公网 IP 直接开 8001，**纯 HTTP 无 TLS** | `https://101.227.232.33:8001` 握手失败（curl 返回 000） |
| 开发主体 | 很可能是**个人/小团队** | 登录页页脚 `©Copyright 2025 Tsi`；全站无厂商/公司信息 |
| 未发现的管理面 | 没有 hangfire / elmah / trace.axd / swagger / /api/v1 / /health | 全部 404（这个是**好消息**，说明没有明显的后台泄漏） |

### 顺手发现的几个加固点（可以直接反馈给学校，很加分）

1. **纯 HTTP 明文**：学生密码在网络上裸奔。你们平台已经是 HTTPS，反而比学校系统安全。
2. **"记住密码"把密码 base64 后写进浏览器 cookie**（`setCookie("password", btoa(...))`）——等价明文存储。
3. **登录无验证码、无失败锁定**：存在撞库/爆破风险（这也是我们能做代验证的前提）。
4. **IIS 的 TRACE 方法是开着的**（`TRACE /Home/Login → 200`），建议关闭；同时建议加 HSTS / X-Frame-Options / CSP 等响应头（目前一个都没有）。
5. 可选：关掉 `X-Powered-By: ASP.NET` 和 Server 版本号，减少指纹泄漏。

## 二、去问负责人该问什么

### 0. 开场（先给结论，别一上来要东西）

> 老师您好，我是 AI 社团社长。我们在学校系统里看到学生区和社团模块（`/Stu/Cas/...`），
> 社团自己的实践平台（wfla-ailab.top）想让社员**用学校账号登录**，省得记两套密码。
> 我们**不保存任何人的学校密码**，学生只在我们页面上输一次、我们拿去学校系统校验一次。
> 想确认三件事：**学校允不允许**、**有没有更规范的单点登录接口可用**、**需要走什么流程**。

### 1. 最关键：有没有统一登录能力（决定走哪条路）

- [ ] 系统有没有**统一身份认证/单点登录**接口？具体是 **OAuth2 / OIDC、CAS、SAML**，还是 **LDAP / AD 绑定**？
- [ ] 如果有，能不能给社团平台注册一个第三方应用（**client_id、回调域名白名单**）？流程多久、谁审批？
- [ ] 有没有**测试/沙箱环境**让我们先联调？
- [ ] 如果短期做不了，**有没有排期**？

### 2. 数据与账号口径

- [ ] 能不能提供**只读**的学生名单（学号/姓名/班级）接口或定期导出，用来做社团白名单？
- [ ] 学号这类数据我们存在自己服务器上，学校允许吗？有**留存/删除**要求吗？
- [ ] 账号唯一标识用哪个字段（学号还是工号）？**会不会随年级变化**？毕业/转学后怎么处理？
- [ ] 一个人会不会有多个账号（比如插班/双学籍）？

### 3. 授权与合规（决定"代验证"这条路能不能走）

- [ ] 社团平台**代学生向学校系统提交一次登录校验**（学生在本平台输入学校账号密码），学校是否允许？需要谁批准？**要不要书面报备**？
- [ ] 有没有**数据安全/隐私**规定或承诺书模板，我们照着写？
- [ ] 学校是否要求我们加上"经学校审核"的说明或免责声明？

### 4. 走"代验证"时必问的技术细节（避免踩坑）

- [ ] `POST /Home/Login` 这个接口**以后会加验证码或风控**吗？接口变更会提前通知我们吗？
- [ ] **同一账号多端登录会不会互踢**？（我们代登录会不会把学生从学校系统挤下线）
- [ ] **连续登录失败会不会锁号**？（我们最怕因为代验证把学生账号弄锁了）
- [ ] 我们的服务器 IP（`68.168.20.247`）**需要加白名单**吗？学校系统是否只允许校内网访问？
- [ ] 有没有**调用频率上限**？我们要不要限流？
- [ ] 有没有接口文档 / 字段说明可以给我们一份？

### 5. 安全加固反馈（顺手做的正事，也显得专业）

- [ ] 现在是 **http 明文**，能否上 **HTTPS**？（我们平台已经是 https，反而是安全的那一侧）
- [ ] 登录页"记住密码"把密码 base64 存进 cookie，建议改成只存用户名或 token。
- [ ] 登录接口没有**验证码/失败锁定**，建议加图形验证码或失败次数限制。
- [ ] IIS 的 **TRACE 方法**建议关闭；建议补上 `HSTS`、`X-Frame-Options` 等响应头。
- [ ] 可选：关闭 `X-Powered-By` 与 Server 版本号。

> ⚠️ 第 5 组一定要用"请教/反馈"的语气，不要说"你们这个有洞"——你是去求合作的，不是去挑刺的。

### 6. 运维协作

- [ ] 系统**维护窗口**是什么时候？（我们好避开）
- [ ] 出故障联系谁？有没有值班/群？
- [ ] 有没有**接口变更通知**机制（版本号、变更日志）？

## 三、不要开口要的东西（会直接把事情谈崩）

- ❌ 学生密码/密码库、任何人的账号密码
- ❌ 管理员账号、数据库直连、服务器登录权限
- ❌ "绕过认证的接口""给我们留个后门账号"
- ❌ 不要提"我们写个脚本批量帮同学登录"——必须是"**学生本人在我们页面登录**，我们只做一次校验"
- ❌ 不要要求学校系统改造来适配我们（应该反过来：我们适配学校）

## 四、怎么问（沟通策略）

1. **找谁**：信息中心/网络管理员是技术决策人，社团指导老师是背书人。**争取两个人一起在场**，或者先跟老师讲一遍再去谈技术。
2. **带什么**：
   - 一页纸：目的 + 数据流图（学生 → 我们 → 学校系统，标注"不存储密码"）+ 我们能随时关掉（`SCHOOL_AUTH_ENABLED=0`）
   - 我们的域名/IP：`wfla-ailab.top`、`68.168.20.247`
   - 想对接的具体接口（如果他们给 OAuth/CAS，我们优先用那个）
3. **留痕**：用邮件或微信文字确认结论，别只靠口头。
4. **给学校留退路**：明确说"如果学校觉得不合适，我们就**不接学校账号**，只做'只有社员能进'的白名单制"——这样对方更容易答应其一。

## 五、两种结果怎么落地

| 学校答复 | 我们的动作 |
|---|---|
| 给了 OAuth/CAS/OIDC | 走真 SSO（最规范），把票据换成本平台账号，白名单照旧 |
| 同意代验证 | 打开 `SCHOOL_AUTH_ENABLED=1`，即本次已实现的方案 |
| 不同意 / 不回 | 退回白名单 + 各自设密码（关聊天站自助注册、手动建号），**不接学校账号** |
